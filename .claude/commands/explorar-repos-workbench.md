# /explorar-repos-workbench

Objetivo:
Explorar repositorios publicos no GitHub que possam agregar ao `workbench`, com foco em metodo, workflow, documentacao, handoff/status e automacao com IA.

Contexto:
Tenho um repositorio chamado `workbench` que funciona como base canonica do meu metodo de trabalho com IA. Ele organiza:
- etapas numeradas (`00-ROTEAMENTO`, `10-DESCOBERTA`, `20-ENTREGA`, `30-REVISAO`, `40-DIAGNOSTICO`, `50-CORRECAO`, `90-LEGADO`)
- arquivos `.md` padronizados (`README`, `prompt`, `checklist`, `saida-esperada`)
- governanca (`CONTEXT`, `HANDOFF`, `STATUS`, `RELATORIO-ATUAL`, `MIGRACAO`)
- camada operacional para IA (`.claude/` com rules, commands, skills, agents)

Tarefa principal:
Explorar repositorios publicos no GitHub com boas praticas de:
- organizacao de workflow
- documentacao de processo
- handoff/status report
- automacao com IA ou dev tools

Regras de busca e analise:
1. Priorizar repositorios que sejam:
   - templates de projeto
   - boilerplates de workflow
   - kits de documentacao
   - frameworks de handoff/status
   - exemplos de IA em dev (`skills`, `agents`, `commands`, `hooks`)
2. Para cada repositorio relevante, extrair:
   - nome e link
   - estrelas aproximadas
   - objetivo do repo (1-2 frases)
   - como organiza pastas, documentacao, templates/processos e automacoes
   - ideias incorporaveis ao `workbench`
   - pontos de atencao (o que nao copiar / riscos)
3. Foco em elementos agregadores para metodo:
   - novos `.md` uteis (decision log, risk log, playbooks)
   - padroes melhores de README/ONBOARDING
   - checklists de handover/status
   - conexao com ferramentas (CI, issues, actions)
   - automacao com IA compativel com o `workbench`
4. Nao focar em codigo de app; focar em estrutura, documentacao e automacao de processo.
